## 1 引言

### 1.1 编写目的

本说明书规定游漫社官方网站（以下简称“本系统”）的功能需求、接口需求、非功能需求、数据需求及验收准则，作为需求分析、设计实现、测试用例编制、测试执行与产品验收的统一依据。

本说明书的预期读者包括：项目组成员、测试人员、维护人员及业务验收人员。

### 1.2 项目背景

本系统为福建师范大学旗山校区游戏协会（对外短名：游漫社）建设的官方站点，同时承担对外信息发布与对内社务协作。系统以单套 Web 应用覆盖桌面浏览器、移动端浏览器及渐进式网页应用（PWA），不另行开发原生应用程序，不上架应用商店。

正式全称：福建师范大学旗山校区游戏协会官方网站。浏览器标题格式为“栏目名 · 游漫社”。

### 1.3 术语与缩写

| 术语 | 定义 |
| --- | --- |
| 本系统 | 游漫社官方网站及其配套服务端接口、数据存储与 QQ 机器人联动能力 |

## 2 总体描述

### 2.1 产品目标

本系统应实现以下目标：

1. 对外完整展示社团定位、部门设置、活动安排、招新说明与联系方式，满足招新展示与日常查阅需要。
2. 对内提供账号审批、活动报名、现场签到、资料查阅、站内消息与成员管理，形成可运营的社务闭环。
3. 通过 QQ 机器人与本系统双向联动：本系统将关键业务事件推送至机器人并由其在 QQ 侧发送消息；机器人可根据约定指令调用本系统接口查询或执行授权操作，并将结果回复至 QQ 会话。
4. 部门、栏目内容与权限配置化，新增部门无需变更信息架构。
5. 适配学生云主机资源，支持桌面与移动端访问，并提供 PWA 安装能力。

### 2.2 用户特征

| 用户类型 | 特征与主要诉求 |
| --- | --- |
| 潜在社员 / 访客 | 了解社团、浏览部门与活动、提交招新意向、完成注册 |
| 在册社员 | 报名与签到、查看个人活动、下载授权资料、收发站内消息、维护个人资料 |
| 工作人员 | 审批成员、发布与运营活动、管理文件与站点内容、查看招新意向与统计信息 |
| 社长 | 全站配置、身份授予、部门设置及关键管理操作 |
| QQ 群管理员 / 值班人员 | 通过 QQ 机器人接收业务提醒，并使用指令查询待办与活动概况 |

### 2.3 运行环境

| 项目 | 要求 |
| --- | --- |
| 应用形态 | Web 全栈单应用，提供页面与 HTTP 接口 |
| 客户端 | 主流桌面浏览器与移动浏览器；支持 PWA 安装 |
| 服务端运行时 | Node.js 18 或以上 |
| 数据存储 | 关系型数据库；部署环境采用 SQLite |
| 文件存储 | 服务器本地磁盘，由反向代理转发应用进程 |
| 主机规格 | 学生云服务器，参考配置为 2 核 2 GB 内存 |
| 网络 | 公网可访问；正式环境应启用 HTTPS |
| 外部系统 | QQ 机器人服务（HTTP Webhook 接收与接口调用） |

### 2.4 约束与假设

1. 本系统采用自建账号（学号与密码），不对接学校统一身份认证。
2. 不开发原生应用程序，不进入应用商店。
3. 第一期不提供自动分组、对阵生成与比分录入；赛事信息以活动或通知形式公示。
4. 不部署独立缓存中间件，以控制主机内存占用。
5. 微信内置浏览器对添加到主屏幕的支持不可靠，系统应提示用户改用系统浏览器；在 iOS 上应提示使用 Safari。
6. 单文件上传体积与头像体积受上限约束，不提供视频直存。
7. QQ 机器人未配置或网络不可达时，不得影响本系统主业务流程的正确完成。

### 2.5 产品功能概览

本系统分为公开区、社员区、管理端与 QQ 机器人联动四部分。

```
公开区：首页、关于社团、部门、活动与通知、招新、登录、注册、PWA 安装指引
社员区：工作台、我的活动、签到、站内消息、资料库、个人资料
管理端：总览、成员、部门、活动运营、文件、招新意向、一言、站点内容与机器人配置
联动：网站事件推送机器人、机器人转发 QQ 消息、机器人指令调用网站接口
```

## 3 角色与权限

### 3.1 角色定义

| 角色标识 | 显示名称 | 说明 |
| --- | --- | --- |
| visitor | 访客 | 未登录，仅可访问公开栏目与公开接口 |
| pending | 待审核 | 注册成功后的默认身份，可浏览公开内容，不可使用内部功能 |
| member | 社员 | 内部功能的主体用户 |
| management | 管理层 | 可进入管理端，执行审批、发布、配置等管理操作 |
| president | 社长 | 最高管理身份，席位唯一；不得被变更为其他身份或停用 |

说明：工作人员可配置称谓（如部长），称谓用于展示，不单独构成权限集合。部门归属与全社角色正交：用户先具备全社角色，再挂接所属部门。

### 3.2 账号状态

| 状态标识 | 显示名称 | 说明 |
| --- | --- | --- |
| pending | 待审 | 尚未完成审批 |
| active | 正常 | 可登录并按角色使用功能 |
| disabled | 停用 | 不得登录 |

### 3.3 权限矩阵

| 功能 | 访客 | 待审核 | 社员 | 管理层 | 社长 |
| --- | --- | --- | --- | --- | --- |
| 浏览公开栏目 | 允许 | 允许 | 允许 | 允许 | 允许 |
| 提交招新意向 | 允许 | 允许 | 允许 | 允许 | 允许 |
| 注册 / 登录 | 允许 | — | — | — | — |
| 活动报名 / 签到 / 评论 | 禁止 | 禁止 | 允许 | 允许 | 允许 |
| 查阅授权文件 | 禁止 | 禁止 | 按可见范围 | 按可见范围 | 按可见范围 |
| 收发站内消息 | 禁止 | 禁止 | 允许 | 允许 | 允许 |
| 维护个人资料 | 禁止 | 禁止 | 允许 | 允许 | 允许 |
| 进入管理端 | 禁止 | 禁止 | 禁止 | 允许 | 允许 |

### 3.4 访问控制通则

1. 未登录用户访问社员区时，系统应引导至登录页；登录成功后应返回原目标页面。
2. 待审核用户或非正常状态用户访问社员区时，系统应引导至待审核说明页。
3. 非工作人员访问管理端时，系统应拒绝并返回社员区。
4. 停用账号不得登录；已停用会话在校验时应失效。
5. 接口应在服务端独立校验身份与权限，不得仅依赖页面隐藏。

## 4 功能需求

本章需求编号格式为 `FR-xx`。每条需求均可判定为通过或失败，作为测试用例追溯依据。

### 4.1 公开门户

#### FR-01 首页展示

**描述：** 系统应提供首页，展示站点首屏文案、随机一言、已发布部门入口、近期已发布活动摘要及招新引导。

**前置条件：** 用户可访问公开站点。

**处理过程：** 系统读取站点配置、已启用一言、已发布部门与近期活动，生成首页。近期活动展示数量应有上限。

**验收准则：** 首页完整呈现上述区块；无数据时对应区块为空或给出空状态，不得出现未处理异常。

#### FR-02 关于社团

**描述：** 系统应提供关于页，展示社团简介、沿革、组织架构与联系方式，并提供部门入口。

**前置条件：** 关于页文案已在管理端配置或存在默认内容。

**处理过程：** 系统按配置项渲染各栏目。

**验收准则：** 各栏目内容与配置一致；部门入口可进入对应部门页。

#### FR-03 部门列表

**描述：** 系统应列出全部已发布部门。

**前置条件：** 存在已发布部门。

**处理过程：** 系统按排序字段输出已发布部门。

**验收准则：** 未发布部门不得出现在公开列表；已发布部门均可进入详情。

#### FR-04 部门详情

**描述：** 系统应展示部门简介、职责、部长寄语及该部门近期活动。

**前置条件：** 部门已发布且访问路径有效。

**处理过程：** 系统按部门标识读取详情及其关联活动。

**验收准则：** 无效标识应返回明确的不存在提示；详情内容与配置一致。

#### FR-05 活动与通知列表

**描述：** 系统应提供活动与通知的公开列表，支持按类型筛选与关键词搜索。

**前置条件：** 存在已发布记录。

**处理过程：** 系统输出已发布的活动与通知；支持按“活动”“通知”筛选及标题搜索。已取消活动若仍对特定角色可见，应标明已取消。

**验收准则：** 筛选与搜索结果正确；未发布记录对访客不可见。

#### FR-06 活动与通知详情

**描述：** 系统应展示标题、封面、时间地点、所属部门、人数与截止信息、正文内容。类型为通知的记录不得提供报名入口。

**前置条件：** 记录已发布。

**处理过程：** 已登录且具备社员权限的用户可看到报名、签到入口（在满足后续条款时）；访客可浏览内容。

**验收准则：** 通知无报名按钮；活动在可报名状态下向合格用户提供报名操作。

#### FR-07 招新页面

**描述：** 系统应提供招新说明与招新意向登记表。登记成功不得自动开通账号。

**前置条件：** 用户可访问招新页。

**处理过程：** 用户填写登记信息并提交；系统保存意向记录，并按 FR-45 尝试通知机器人。

**验收准则：** 必填项缺失时拒绝提交并提示；提交成功后给出确认，管理端可查阅该记录。

#### FR-08 赛事信息公示

**描述：** 系统应将赛事承办信息作为活动或通知予以公示，展示名称、时间地点、项目或说明、报名方式及成绩或海报等信息。

**前置条件：** 工作人员已发布相应记录。

**处理过程：** 用户通过活动与通知栏目查阅。

**验收准则：** 用户可完整阅读公示信息；系统不提供自动对阵与比分录入。

### 4.2 账号与会话

#### FR-09 用户注册

**描述：** 系统应允许访客使用学号、姓名、邮箱、密码及招新相关资料字段完成注册。密码长度应不少于 8 位。学号与邮箱应唯一。

**前置条件：** 学号与邮箱尚未被占用。

**处理过程：** 系统校验必填项与密码长度；对密码进行不可逆存储；创建账号，角色与状态均为待审核；建立登录会话；写入审计记录；按 FR-45 推送 `member_pending` 事件。

**验收准则：** 校验失败返回明确原因；学号或邮箱重复时拒绝注册；成功后用户进入待审核状态，且不可使用内部功能。

**注册字段：**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 姓名 | 是 | 与学生证一致 |
| 学号 | 是 | 登录标识 |
| 学院 | 是 | 如软件学院 |
| 年级 | 是 | 如 2024 级 |
| 手机号 | 是 | 用于联络 |
| QQ | 是 | 用于社群联络 |
| 邮箱 | 是 | 账号标识 |
| 意向部门 | 否 | 挂接已有部门 |
| 游戏方向 | 否 | 自由填写 |
| 自我介绍 | 否 | 简要说明 |
| 密码 | 是 | 不少于 8 位 |

#### FR-10 用户登录

**描述：** 系统应支持学号与密码登录。登录成功后建立会话。

**前置条件：** 账号已存在。

**处理过程：** 系统校验凭据与账号状态；停用账号不得登录；成功后写入审计记录。待审核用户登录后应进入待审核说明页。

**验收准则：** 凭据错误时应提示登录失败，不得返回系统内部细节；停用账号无法登录；待审核用户不能进入社员区。

#### FR-11 退出登录

**描述：** 已登录用户应能退出。退出后会话失效。

**验收准则：** 退出后访问社员区被要求重新登录。

#### FR-12 待审核限制

**描述：** 待审核用户仅可浏览公开内容与查看审核状态说明，不得报名、签到、评论、下载内部文件或使用站内消息。

**验收准则：** 直接访问社员区路径时被拦截并导向待审核页；相关接口返回未授权。

#### FR-13 账号停用

**描述：** 工作人员可将成员账号置为停用。停用账号不得登录。社长账号不得被停用。

**验收准则：** 停用立即生效；对社长执行停用应被拒绝。

### 4.3 活动报名、签到与互动

#### FR-14 活动报名

**描述：** 已审核社员应能在报名截止前、名额未满、活动未取消且类型为活动时提交报名。同一用户对同一活动仅能报名一次。

**前置条件：** 用户身份为已审核社员；活动已发布、未取消、类型为活动。

**处理过程：** 系统校验截止时间、容量与重复报名后写入报名记录。

**验收准则：** 截止后、满员、已报名、通知类型或已取消时均不得报名，并给出相应提示。

#### FR-15 取消报名

**描述：** 已报名且活动未取消、报名仍处于可取消规则内时，社员应能取消报名。

**验收准则：** 取消后该用户不再出现在有效报名名单中，可在仍满足 FR-14 时重新报名。

#### FR-16 口令签到

**描述：** 在工作人员开启签到后，已报名社员应能凭现场口令完成签到。口令比对不区分大小写。未报名用户不得签到。

**前置条件：** 签到已开启；用户已报名；口令正确。

**处理过程：** 系统记录签到方式为口令，同一活动同一用户仅能成功签到一次。

**验收准则：** 错误口令失败；重复签到失败；未开启签到时失败。

#### FR-17 动态二维码签到

**描述：** 工作人员开启签到后，系统应生成带活动标识与一次性校验参数的签到二维码，并定时刷新校验参数，以降低截图转发后长期有效的风险。已报名社员扫描有效二维码后完成签到。

**前置条件：** 签到已开启；二维码仍在有效期内；用户已报名并已登录。

**处理过程：** 未登录用户扫描后应先登录再完成签到。过期二维码不得签到成功。

**验收准则：** 有效码可签到；过期码失败；未报名失败；同一用户不可重复签到。

#### FR-18 活动评论

**描述：** 已审核社员应能对已发布活动发表评论，评论长度应有上限。

**验收准则：** 未登录或待审核用户不能评论；超长内容被拒绝；评论在详情页可见。

#### FR-19 活动点赞与评论点赞

**描述：** 已审核社员应能对活动或评论点赞，同一用户对同一对象仅能点赞一次；再次操作应取消点赞或保持幂等的可预期行为，并以界面状态为准保持一致。

**验收准则：** 点赞计数正确；未授权用户无法点赞。

### 4.4 社员工作台、消息与资料

#### FR-20 社员工作台

**描述：** 已审核社员登录后应能进入工作台，查看头像、已报名数量、已签到数量及近期报名摘要。

**验收准则：** 统计与该用户实际报名、签到记录一致。

#### FR-21 我的活动

**描述：** 系统应列出当前用户已报名的活动，并提供口令签到入口（在签到开启时）。

**验收准则：** 仅显示本人报名记录；已取消活动有明确状态标识。

#### FR-22 站内消息列表与未读

**描述：** 系统应为社员提供站内消息列表，区分系统通知与私信，展示未读数量，并支持将单条消息标记为已读。

**验收准则：** 新消息计入未读；标记已读后未读数减少；用户只能看到发送给本人的消息。

#### FR-23 社员私信

**描述：** 已审核社员应能按姓名或学号检索其他成员并向其发送私信。

**验收准则：** 发送成功后对方收件箱可见；不得向不存在的用户发送。

#### FR-24 活动开始与结束通知

**描述：** 当已发布且未取消的活动到达开始时间或结束时间时，系统应向该活动有效报名者发送站内系统通知，且同一阶段不得重复发送。

**验收准则：** 开始通知与结束通知各至多一次；取消的活动不再补发开始或结束通知。

#### FR-25 资料库查阅与下载

**描述：** 已审核社员应按文件可见范围查阅并下载资料。可见范围包括：公开、全社、本部门、管理级。

**处理过程：**

| 可见范围 | 可访问对象 |
| --- | --- |
| 公开 | 已审核社员 |
| 全社 | 已审核社员 |
| 本部门 | 所属部门与该文件部门一致的已审核用户，以及工作人员 |
| 管理级 | 仅工作人员 |

**验收准则：** 越权用户在列表中不可见或下载被拒绝；授权用户可成功下载。

#### FR-26 个人资料与头像

**描述：** 已审核社员应能修改手机、QQ、游戏方向、简介并上传头像。头像文件大小不得超过 2 MB。工作人员可维护称谓。用户不得通过本功能自行修改身份角色。

**验收准则：** 合法修改立即生效；超限头像被拒绝；普通社员不能把自身角色改为管理层或社长。

### 4.5 管理端

#### FR-27 管理端入口与总览

**描述：** 工作人员应能进入管理端，查看成员数量、活动数量、招新意向数量及近期审计记录。

**验收准则：** 非工作人员无法进入；统计与数据一致。

#### FR-28 成员列表与档案

**描述：** 工作人员应能按身份、部门、状态筛选成员，并查看成员档案、活动参与记录。

**验收准则：** 筛选结果正确；档案信息完整。

#### FR-29 成员审批与部门分配

**描述：** 工作人员应能将待审核用户审批为社员或工作人员，分配部门，调整状态，以及维护称谓。不得将社长变更为其他身份，不得停用社长，不得通过普通审批操作另设第二名社长。

**验收准则：** 审批后用户可使用对应权限；非法变更被拒绝。

#### FR-30 重置成员密码

**描述：** 工作人员应能在成员档案中重置该成员密码。重置后应使用新密码方可登录。

**验收准则：** 旧密码立即失效；本人操作对象明确，不得误重置无关账号。

#### FR-31 部门配置

**描述：** 工作人员应能新增部门并维护名称、路径标识、简介、职责、部长寄语、色调、排序及是否发布。新增部门后，公开导航与首页应自动出现该部门，无需变更信息架构。

**验收准则：** 发布后公开可见；取消发布后公开不可见；路径标识唯一。

#### FR-32 活动发布与编辑

**描述：** 工作人员应能发布和编辑活动或通知，字段包括标题、类型、封面、时间地点、所属部门、人数上限、报名截止、详情正文、是否需要签到及是否发布。

**验收准则：** 必填缺失时不得发布；已发布记录按 FR-05、FR-06 可见。

#### FR-33 取消活动

**描述：** 工作人员应能取消已发布活动。取消后应关闭签到，向有效报名者发送站内取消通知，并按 FR-45 推送 `event_cancel` 事件。

**验收准则：** 取消后不得继续报名或签到；报名者收到取消通知。

#### FR-34 签到开关与现场核验

**描述：** 工作人员应能为指定活动开启或关闭签到，查看或设置口令，并展示动态二维码供现场核验。

**验收准则：** 关闭后新的签到请求失败；开启后口令与二维码两种方式均可用。

#### FR-35 报名与签到名单导出

**描述：** 工作人员应能导出指定活动的报名与签到名单。

**验收准则：** 导出文件包含关键字段（姓名、学号、报名时间、是否签到等），与系统内记录一致。

#### FR-36 向报名者群发消息

**描述：** 工作人员应能向指定活动的全部有效报名者发送一条站内消息。

**验收准则：** 每位有效报名者收到一条；返回通知人数与实际写入数一致。

#### FR-37 文件上传与删除

**描述：** 工作人员应能上传资料并设置标题、分类与可见范围，应能删除文件。单文件大小不得超过 20 MB。分类包括：社团制度、使用说明、活动资料、开发工具、作品存档、研发文档、教程资源。

**验收准则：** 超限文件被拒绝；删除后不可再下载；可见范围立即生效。

#### FR-38 招新意向查阅

**描述：** 工作人员应能查看招新意向列表，包含登记字段与提交时间。本功能为查阅，不自动开户。

**验收准则：** 列表与提交记录一致，按时间可追溯。

#### FR-39 一言管理

**描述：** 工作人员应能新增、启用、停用或删除一言。首页仅随机展示已启用条目。

**验收准则：** 停用或删除后不再出现在首页随机展示中。

#### FR-40 站点内容配置

**描述：** 工作人员应能维护首页文案、关于页文案、招新相关说明、QQ 群信息、背景装饰开关，以及 QQ 机器人 Webhook 地址与共享密钥。

**验收准则：** 保存后公开页展示与配置一致；机器人参数按 FR-44 生效。

#### FR-41 审计记录

**描述：** 系统应对注册、登录、成员变更、活动运营、站点配置等关键操作写入审计日志，记录操作者、动作与必要详情。

**验收准则：** 管理端总览可查阅近期审计记录；记录不可被普通用户篡改。

### 4.6 PWA

#### FR-42 PWA 安装与独立打开

**描述：** 系统应提供可安装的 PWA，包含应用名称、图标与主题色，支持添加到主屏幕后以独立窗口打开。系统应提供安装说明页，并提示在微信内改用系统浏览器、在 iOS 上使用 Safari。

**验收准则：** 支持 PWA 的浏览器可识别清单信息；说明页文案明确；不影响未安装用户的普通浏览。

### 4.7 QQ 机器人联动

本模块为本系统特色能力。联动关系如下：本系统在约定业务事件发生时向机器人推送消息，机器人在 QQ 群或管理员会话中发送文本；用户在 QQ 中向机器人发送约定指令后，机器人调用本系统接口并将结果回复至该会话。

#### FR-43 机器人参数配置

**描述：** 工作人员应能在站点内容配置中维护机器人 Webhook 地址与共享密钥。地址为空或不是以 `http://`、`https://` 开头的合法 URL 时，系统不得发起推送。

**验收准则：** 保存后立即作为后续推送与校验依据；错误地址不得导致管理端保存失败。

#### FR-44 推送失败隔离

**描述：** 机器人未配置、密钥错误、网络失败或对端超时时，本系统主业务（注册、招新登记、活动取消等）仍应成功落库并返回成功。推送失败不得向最终用户报错为业务失败。

**验收准则：** 断开机器人后，注册、招新、取消活动的主流程仍成功。

#### FR-45 业务事件出站通知

**描述：** 在已配置有效 Webhook 时，系统应在下列事件发生后向该地址发送 HTTP POST，请求头携带共享密钥，请求体为 JSON，并包含事件时间。

| 事件类型 `type` | 触发时机 | 请求体业务字段 |
| --- | --- | --- |
| member_pending | 用户注册成功且进入待审核 | name，studentId |
| recruit | 招新意向提交成功 | name，studentId |
| event_cancel | 活动取消成功 | title，eventId，notified |

**验收准则：** 三类事件均能在机器人接收端观察到对应 JSON；字段完整；未配置时不发送。

#### FR-46 机器人向 QQ 发送消息

**描述：** QQ 机器人在校验共享密钥成功后，应将 FR-45 事件转写为可读中文消息，发送至约定的 QQ 群或管理员会话。

**消息内容最低要求：**

| 事件类型 | 消息应包含的信息 |
| --- | --- |
| member_pending | 待审核提醒、姓名、学号 |
| recruit | 招新意向提醒、姓名、学号 |
| event_cancel | 活动取消提醒、活动标题、站内已通知人数 |

**验收准则：** 对应 QQ 会话在事件发生后收到一条完整可读消息；密钥错误时不得发送。

#### FR-47 机器人指令与接口调用

**描述：** QQ 机器人应能识别约定指令，在校验共享密钥后调用本系统接口，并将结果回复到当前 QQ 会话。指令大小写不敏感，允许前后空白。

| 指令 | 动作 | 调用能力 | 回复最低要求 |
| --- | --- | --- | --- |
| 帮助 | 列出可用指令 | 无 | 包含本表全部指令名称 |
| 活动 | 查询近期已发布活动 | 读取公开活动列表 | 标题、开始时间；无数据时明确说明 |
| 待审 | 查询待审核成员 | 读取待审成员摘要 | 人数；有记录时给出姓名与学号摘要 |
| 招新 | 查询招新意向 | 读取招新意向摘要 | 条数；有记录时给出最近登记摘要 |
| 报名 | 查询指定活动报名概况 | 读取报名人数 | 需活动标识或标题；回复已报名人数与容量 |

**验收准则：** 合法指令返回与系统数据一致的结果；未知指令回复帮助或无法识别说明；接口失败时回复失败原因，不得假装成功。

#### FR-48 机器人调用鉴权

**描述：** 凡由机器人发起的本系统接口调用，均应携带共享密钥。密钥缺失、错误或空配置时，系统应拒绝调用，不得返回待审名单、招新意向等非公开数据。

**验收准则：** 错误密钥调用管理类查询返回失败；不得泄露未公开个人信息。

#### FR-49 机器人最小权限

**描述：** 机器人默认仅具备查询类能力及 FR-47 所列授权操作。机器人不得通过指令修改社长身份、删除全部数据或重置任意用户密码。若需触发管理侧通知类操作，应限于已明确授权的活动群发或等价通知，并写入审计记录。

**验收准则：** 越权指令被拒绝；授权操作可在审计中追溯。

## 5 接口需求

本章编号格式为 `IF-xx`。接口均以 HTTP 与 JSON 为默认交互方式。除另有说明外，成功响应的 HTTP 状态码为 200，客户端错误为 4xx，服务端错误为 5xx。

### 5.1 接口通则

#### IF-01 编码与格式

请求与响应应使用 UTF-8。JSON 请求的 `Content-Type` 应为 `application/json`。时间字段应使用可解析的日期时间格式。

#### IF-02 会话

登录成功后，系统应通过 Cookie 维持会话。受保护接口在会话缺失、过期或权限不足时应拒绝访问。

#### IF-03 错误表示

接口失败时应返回明确的状态说明，供页面或机器人展示。不得将堆栈信息返回给未授权调用方。

| --- | --- |
| Content-Type | application/json |
| x-bot-secret | 共享密钥；未配置时为空字符串 |

**请求体通用字段：**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| at | string | 事件时间，ISO 8601 |
| type | string | 事件类型，见 FR-45 |

**示例一：成员待审**

```json
{
  "at": "2026-09-17T12:00:00.000Z",
  "type": "member_pending",
  "name": "张三",
  "studentId": "20210001"
}
```

**示例二：招新意向**

```json
{
  "at": "2026-09-17T12:05:00.000Z",
  "type": "recruit",
  "name": "李四",
  "studentId": "20210099"
}
```

**示例三：活动取消**

```json
{
  "at": "2026-09-17T13:00:00.000Z",
  "type": "event_cancel",
  "title": "秋季体验赛",
  "eventId": "示例活动标识",
  "notified": 12
}
```

**处理要求：** 机器人应校验 `x-bot-secret` 与本地配置一致后再发送 QQ 消息。校验失败应丢弃该请求。

#### IF-09 机器人调用网站接口

**方向：** QQ 机器人 → 本系统。

机器人应以 HTTP 调用本系统业务接口完成 FR-47 所列查询。调用管理类或非公开数据时，应使用工作人员会话或与共享密钥绑定的机器人调用凭据，并满足 FR-48。

**推荐查询对应关系：**

| 指令 | 对应接口 | 说明 |
| --- | --- | --- |
| 活动 | GET /api/public/events | 仅已发布数据 |
| 待审 | GET /api/admin/members，筛选待审核 | 需鉴权 |
| 招新 | GET /api/admin/recruit | 需鉴权 |
| 报名 | GET /api/admin/events/{id} 或公开详情中的报名统计 | 按权限取最小必要字段 |

**密钥校验失败时的响应要求：** 返回 401 或 403，不返回成员与招新明细。

#### IF-10 机器人 QQ 消息格式

机器人发往 QQ 的文本消息应使用简体中文，一行或多行均可，但应可读、应避免堆砌未解释的原始 JSON。查询类回复在记录较多时应截断并注明总数。

## 6 非功能需求

本章编号格式为 `NFR-xx`。

### 6.1 性能

#### NFR-01 页面响应

在参考主机规格、并发用户不超过 50 的条件下，公开页与社员常用页的首屏 HTML 响应时间在正常网络下应不超过 3 秒。

#### NFR-02 接口响应

常用查询接口在上述条件下的服务端处理时间应不超过 2 秒。名单导出可适当延长，但应在 10 秒内返回或提供明确进行中状态。

#### NFR-03 签到并发

单场活动在签到开启期间，系统应支持现场多人连续签到，不得因普通并发出现重复签到成功或数据丢失。

#### NFR-04 资源占用

系统应能在 2 核 2 GB 内存的学生云主机上稳定运行，不依赖额外缓存服务。

### 6.2 安全性

#### NFR-05 口令存储

用户密码应使用不可逆哈希存储，不得明文保存。

#### NFR-06 传输安全

正式环境应使用 HTTPS。会话 Cookie 在启用安全传输时不应被明文站点滥用。

#### NFR-07 权限强制

所有写操作与非公开读操作应在服务端鉴权。不得仅靠隐藏按钮实现权限。

#### NFR-08 机器人密钥

共享密钥不得出现在公开页面文案中。公开接口返回的配置数据不得包含共享密钥。

#### NFR-09 上传约束

头像不超过 2 MB，资料文件不超过 20 MB。系统应拒绝超限文件。

#### NFR-10 审计

关键管理操作应可追溯至操作者。

#### NFR-11 敏感操作保护

社长身份与停用限制按第 3 章执行。重置密码仅工作人员可对明确目标账号执行。

### 6.3 兼容性与可用性

#### NFR-12 浏览器

系统应支持近两年主流版本的 Chrome、Edge、Firefox 与 Safari，以及 iOS、Android 系统浏览器。布局应适配常见桌面宽度与移动端竖屏。

#### NFR-13 语言

用户可见文案应为简体中文。

#### NFR-14 空状态与错误

列表为空、权限不足、网络失败时应给出明确说明，不得出现空白崩溃页。

#### NFR-15 PWA 限制说明

对微信内置浏览器与 iOS 添加主屏幕的限制，应在安装说明中明示。

### 6.4 可维护性与可扩展性

#### NFR-16 部门扩展

新增部门应仅通过管理端配置完成，公开导航与首页自动更新。

#### NFR-17 内容可配置

首页、关于页、联系方式、招新说明等文案应可在管理端修改，无需为改文案调整信息架构。

#### NFR-18 备份

部署方应对数据库文件与上传目录进行定期备份。系统应保证上述数据具有明确的存储位置，便于备份。

## 7 数据需求

### 7.1 实体一览

| 实体 | 说明 |
| --- | --- |
| 部门 | 社团组织单元 |
| 用户 | 账号与个人资料 |
| 会话 | 登录态 |
| 活动 | 活动或通知 |
| 报名 | 用户与活动的报名关系 |
| 签到 | 用户与活动的签到记录 |

| 一言 | 首页语句 |
| 站内消息 | 系统通知或私信 |
| 站点配置 | 键值配置，含机器人参数 |
| 审计日志 | 关键操作记录 |

### 7.2 关键字段

#### 部门

名称、路径标识（唯一）、简介、职责、部长寄语、色调、排序、是否发布。

#### 用户

学号（唯一）、邮箱（唯一）、密码哈希、姓名、学院、年级、手机、QQ、游戏方向、简介、头像、角色、状态、称谓、所属部门。

#### 活动

标题、类型（活动 / 通知）、封面、开始时间、结束时间、地点、报名截止、人数上限、所属部门、是否需要签到、签到是否开启、签到口令、动态校验参数及过期时间、是否发布、取消时间、开始通知已发送、结束通知已发送。

#### 报名与签到

报名：活动、用户、报名时间；同一活动同一用户唯一。  
签到：活动、用户、签到方式（口令 / 二维码）、签到时间；同一活动同一用户唯一。

#### 文件

标题、存储名、分类、可见范围、所属部门、上传者、大小、类型。

#### 招新意向

姓名、学号、学院、年级、手机、QQ、邮箱、意向部门、游戏方向、自我介绍、提交时间。

#### 站内消息

类型（私信 / 系统）、系统子类型、关联活动、发件人、标题、正文、收件人、已读时间。

#### 站点配置

键、值。其中应包含机器人 Webhook 地址与共享密钥。

#### 审计日志

动作、详情、操作者、时间。

### 7.3 完整性与约束

1. 学号、邮箱、部门路径标识应唯一。
2. 删除或取消活动不得导致报名者历史记录无法审计；取消以状态标识，保留名单。
3. 文件删除后，对应存储对象应不可再通过原下载入口获取。
4. 站内消息收件人必须为有效用户。

## 9 验收标准

本章按模块给出通过条件。全部条件满足则该模块验收通过。

### 9.1 公开门户

1. 首页、关于、部门、活动、招新页面可访问，内容与配置一致。
2. 未发布部门与未发布活动对访客不可见。
3. 招新意向提交后管理端可见，且不自动开户。

### 9.2 账号与权限

1. 注册、登录、退出符合 FR-09 至 FR-13。
2. 待审核用户不能使用内部功能。
3. 停用账号不能登录；社长不能被停用或改身份。
4. 非工作人员不能进入管理端。

### 9.3 活动闭环

1. 发布、报名、取消报名、口令签到、二维码签到、评论与点赞符合对应需求。
2. 满员、截止、未报名、签到关闭、二维码过期等负面路径均被拒绝。
3. 取消活动后报名者收到站内通知，且不能继续报名或签到。
4. 活动开始与结束通知各不重复。
5. 名单导出与系统记录一致。

### 9.4 消息与文件

1. 私信、系统通知、未读与已读状态正确。
2. 文件四级可见范围均得到遵守。
3. 上传与下载限制生效。

### 9.5 管理端

1. 成员审批、部门配置、活动运营、文件、招新查阅、一言、站点配置功能可用。
2. 审计记录对关键操作可见。

### 9.6 PWA

1. 存在清单与安装说明。
2. 对微信及 iOS 限制有明确提示。

### 9.7 QQ 机器人联动

1. 三类出站事件在已配置条件下均可被接收，报文符合 IF-08。
2. QQ 侧消息内容满足 FR-46。
3. 指令“帮助”“活动”“待审”“招新”“报名”行为满足 FR-47。
4. 错误密钥不能获取非公开数据。
5. 机器人关闭时，网站主流程仍成功。

### 9.8 非功能

1. 参考环境下页面与接口满足第 6 章时限。
2. 密码非明文；正式环境可启用 HTTPS。
3. 公开响应不包含机器人共享密钥。

# 福建师范大学旗山校区游戏协会（游漫社）官方网站策划案

| 项目 | 说明 |
| --- | --- |
| 项目名称 | 游漫社官方网站 |
| 主办单位 | 福建师范大学旗山校区游戏协会（游漫社） |
| 站点形态 | 单套 Web 站点（桌面浏览器 + 移动端 H5 + PWA） |
| 不上架 | 不开发原生 App，不进入应用商店 |
| 品牌调性 | 独立游戏 / 游漫风：色彩、插画感、创作社群；对外端庄可查，对内有社群温度 |
| 服务对象 | 在册社员、招新对象、校团委及相关单位查阅 |
| 建议域名 | `youman.fjnu.edu.cn`（以校团委实际核发的二级域名为准） |
| 运行环境 | 学生云服务器（约 2 核 2G）+ 学校二级域名 HTTPS |

---

## 一、立项依据与建设目标

本站同时承担社团**对外门面**与**对内工作台**。访客可了解社团定位、部门设置、活动安排与赛事承办情况；经审批的社员可登录完成活动报名、现场签到与资料查阅。以 PWA（渐进式网页应用）实现“添加到主屏幕、全屏打开、底部导航”的近 App 体验，规避原生应用上架审核。

建设目标如下：

1. **场面**：视觉完成度高，可用于招新摊位展示、团委检查与对外合作说明。
2. **实用**：活动发布、报名、签到形成闭环；文件与赛事信息入口固定、可检索。
3. **可维护**：部门、角色、栏目配置化，后续增设部门无需改动核心架构。
4. **可落地**：适配学生云主机资源与学校二级域名备案路径。

## 三、用户角色与权限

采用自建账号（学号 + 邮箱 + 密码）。不对接学校统一身份认证。新注册账号默认为“待审核”，管理层通过后方可使用内部功能。

| 角色 | 权限概要 |
| --- | --- |
| 访客 | 浏览公开栏目 |
| 待审核 | 查看审核状态与公开内容 |
| 社员 | 报名、签到、下载授权文件、维护个人资料 |
| 部长 / 副部长 | 维护本部门主页、本部门活动与文件 |
| 管理层 | 审批成员、发布全社活动与赛事、管理全站文件、查看数据 |
| 社长 | 全站配置、角色授予、部门增删、危险操作 |

部门身份与全社角色正交：成员先具备全社角色，再挂接“电竞部”“游戏研发部”等部门。新增部门仅增加配置记录，不新增一套权限代码。

---

## 四、信息架构

公开区与登录区分离。桌面端为顶栏导航；移动端公开页为顶栏，登录后为底部主导航，接近 App。

### 4.1 公开栏目

- **首页**：品牌首屏、近期活动、部门入口、赛事速览、招新引导、安装桌面提示。
- **关于社团**：简介、沿革、组织架构、联系方式、指导单位口径。
- **部门**：电竞部、游戏研发部（数据驱动，可增部）。含简介、职责、近期动态、部长寄语。
- **活动**：列表与详情；登录后可报名。
- **赛事承办**：赛事信息、项目设置、报名说明、规程与成绩公示。第一期不做自动对阵与比分系统。
- **招新**：流程说明、常见问题、意向登记。

### 4.2 社员区

- 工作台、我的活动、扫码/口令签到、文件库、个人中心。

### 4.3 管理端

- 成员审批与角色部门分配、活动管理（含签到码与名单导出）、赛事信息、文件库、招新意向、部门与站点配置。管理端为响应式网页，不另做后台 App。

## 五、功能规格

### 5.1 账号

- 注册字段见《素材与信息清单》中的招新/注册字段。
- 登录、退出；找回密码走邮箱验证码（服务器未配置 SMTP 时，可由管理层在后台重置）。
- 关键操作写入审计日志。

### 5.2 活动与签到

- 活动含标题、封面、时间地点、所属（全社或某部门）、人数上限、报名截止、详情、是否签到。
- 社员可在截止前报名或取消；满员后停止报名。
- 签到同时支持：**动态二维码**（定时刷新，降低截图转发有效性）与**现场口令**。
- 报名名单可导出，出勤可按场次查阅。

### 5.3 赛事承办

- 展示赛事名称、时间地点、项目、报名方式、规程附件、成绩或海报公示。
- 第一期不包含分组、对阵生成、比分录入。

### 5.4 文件库

- 分类：社团制度、活动资料、赛事规程、研发文档、教程资源。
- 可见范围：公开 / 全社 / 某部门 / 管理层。
- 限制单文件大小与总容量，优先文档、图片与压缩包。

### 5.5 部门模块

- 部门为配置实体：名称、简介、封面、排序、是否展示。
- 活动、文件、干部身份均挂接部门。
- 管理端新增部门后，导航与首页自动出现该部门。

### 5.6 PWA

- 可安装、全屏显示、自定义图标与启动屏。
- 微信内置浏览器无法可靠添加到桌面，站点需提示改用系统浏览器（iOS 为 Safari）。

## 六、视觉原则

独立游戏社群风格：纸色底、印戳与插画块面、珊瑚与青绿对比，避免电竞深黑风与公文排版风。招新与团委查阅场景下，信息层级清楚、正文可读。

---

## 七、技术与部署

- 形态：TypeScript 全栈单应用（Nuxt 3 + Prisma）。本地开发使用 SQLite，便于直接运行；生产环境切换 MySQL 8。
- 上传文件存本机磁盘，由 Nginx 反代 Node 进程。
- 不部署 Redis，以控制学生机内存。
- 域名使用学校二级域名并启用 HTTPS；数据库与上传目录定时备份。

---

## 八、实施步骤

1. 视觉规范与栏目文案、标志及照片。
2. 公开站骨架、响应式与 PWA。
3. 账号审批、角色与部门配置。
4. 活动发布、报名、二维码与口令签到、名单导出。
5. 赛事信息与文件库。
6. 管理端打磨、学生机部署、域名与备份。

---

## 九、风险

- 学生机磁盘与带宽有限，须限制上传体积，避免视频直存。
- 域名与备案进度取决于学校，开发可用临时域名。
- iOS 须经 Safari 添加主屏幕；微信内能力受限。
- 成员信息按最小权限管理，传输使用 HTTPS。
